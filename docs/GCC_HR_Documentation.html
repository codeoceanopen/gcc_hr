Internal reference · v0.0.1

A compliance layer on top of Frappe HR, not a replacement for it.

GCC HR extends standard ERPNext and Frappe HR with the labor-law, government-filing, and nationalization-quota logic that six Gulf countries each require, without ever editing Frappe/ERPNext/HRMS core. Every extension is a hook, a custom field, or a new doctype layered on top of doctypes you already know — Employee, Contract, Salary Slip, Gratuity.

01 · Architecture

One core, six country plugins, one company-driven frontend

Every country's payroll and labor rules live in an isolated package. The Vue SPA reads which country is active from the currently-selected company and shows only that country's menus — never a mix, never a guess.

The "two folders per country" rule

Frappe resolves a doctype's module by looking for it directly under gcc_hr/gcc_hr/<module>/doctype/. That forces every country to be split into two sibling folders: business logic lives in countries/<slug>/ (saudization.py, gosi.py, rules.py, setup.py…), while its doctypes live in gcc_hr/<slug>/doctype/. Every one of the six countries repeats this exact split.

Company-first, not country-first

The frontend never asks "which country are you in." It asks "which company," resolves that company's country from GCC HR Company Settings, and drives everything else from there — sidebar sections, dashboard panels, quota calculations. Switching the company switches the whole application's context in one action.

02 · Security model

UI visibility is not security

The sidebar hides Saudi menus for a Qatar company. That's a convenience, not a boundary — the backend enforces the real one, independently, on every write.

Cross-country enforcement

enforce_company_country(company, expected_country) is called from every country-specific doctype's validate() and every whitelisted recalculate_now/simulate API — before UI existed to hide anything. A Saudization Profile literally cannot be created for a company configured as Qatar.

Role-based access

10 roles (System Manager down to per-domain Officers) with a full create/write/delete matrix per doctype. Engine-written doctypes — HR Compliance Check, HR Audit Log, every *ization Profile — accept no manual create from anyone but an administrator.

Immutable audit trail

HR Audit Log is insert-only. Compliance checks are never edited after the fact. Government submissions move through a one-way state machine (Draft → Generated → Validated → Ready → Submitted → Response Uploaded → Completed), re-checked server-side at every transition.

No fabricated integrations

Neither MHRSD/Nitaqat nor GOSI expose a verified public API — so Government Integration never claims to call one. It generates the real document a human takes to the real portal, and tracks the outcome. Same honesty policy across all six countries.

No secrets exist in this codebase. Future government-portal credentials must use Frappe's own Password fieldtype — never a plaintext field or a fixture.

06 · Deep dive

Saudi annual leave: entitlement, carry-forward, cash-out

The newest module. Built on HRMS's own leave engine rather than a parallel one — this app adds exactly two things HRMS doesn't already have: the tenure-based entitlement rule, and a compliance check that flags under-allocation.

What HRMS already does

Leave Type, Leave Allocation, and Leave Encashment already implement carry-forward and cash-out correctly — a Leave Type can be flagged is_carry_forward with a maximum and an expiry window, and allow_encashment with a per-day rate pulled from the employee's Salary Structure Assignment. GCC HR configures this engine for Saudi Arabia; it does not reimplement it.

What GCC HR adds

Seeded Leave Type

"Saudi Annual Leave" — carry-forward up to 30 days, expiring after 2 years (KSA practice of accumulating leave by agreement); encashment up to 30 days against the Basic salary component.

Tenure-based entitlement

KSA Labour Law Art. 109: 21 calendar days/year under 5 years of service, 30 days/year from the 5th year onward. A pure function, unit-tested at both boundaries.

The compliance rule

SA_ANNUAL_LEAVE_ENTITLEMENT reads each employee's latest submitted allocation and compares it against their tenure-appropriate entitlement — a soft, scored finding through the same engine every other Saudi rule runs through, not a hard block on the Leave Allocation doctype. Allocating leave stays an HR decision; the engine just tells you when it falls short. 

# countries/saudi_arabia/leave.py
def get_annual_leave_entitlement(date_of_joining, on_date=None) -> int:
    """KSA Labour Law Art. 109: 21 days/year under 5 years of service,
    30 days/year from the 5th year onward."""
    years_of_service = (getdate(on_date or today()) - getdate(date_of_joining)).days / 365.25
    return 30 if years_of_service >= 5 else 21

07 · Operating it

Setup & installation

# install onto an existing bench
bench get-app gcc_hr
bench --site mysite.local install-app gcc_hr

# frontend dev loop
cd apps/gcc_hr/frontend
yarn install
yarn dev        # local dev server
yarn build      # production build -> gcc_hr/public/frontend

# sync built assets + clear stale caches
bench build --app gcc_hr
bench --site mysite.local clear-cache

Required apps: erpnext, hrms (declared in hooks.py's required_apps; Frappe itself is implicit). Country setup (document types, compliance rules, gratuity rules, government submission types) runs automatically the first time a company's country is set, dispatched from GCC HR Company Settings.on_update.

Testing

bench run-tests --app gcc_hr can crash inside ERPNext's own legacy test-record preloader on a site that already has real Company data — a pre-existing ERPNext quirk, not a gcc_hr bug. The project's own workaround runs the suite directly inside bench console, wrapped in a savepoint that's always rolled back: 

# inside `bench --site <site> console`
import unittest, importlib, frappe
suite = unittest.TestSuite()
# ...load each gcc_hr.*.test_* module...
frappe.db.savepoint("gcc_hr_test_run")
frappe.db._disable_transaction_control = True
try:
    unittest.TextTestRunner(verbosity=2).run(suite)
finally:
    frappe.db._disable_transaction_control = False
    frappe.db.rollback(save_point="gcc_hr_test_run")
